# RoboMaster Simulation

基于 Godot 4 的 RoboMaster 仿真项目，旨在构建机器人运动、场地交互与视觉通信环境，为后续计算机视觉算法接入和仿真测试提供基础。

## 1. 项目简介

本项目使用 Godot 4 开发 RoboMaster 风格的三维仿真环境，逐步实现机器人运动、碰撞检测、子弹发射、场景交互，以及 Godot 与 Python 视觉程序之间的通信。

项目以仿真场景搭建、机器人基础行为和视觉通信为主要开发方向，为后续视觉识别算法接入和比赛仿真功能扩展提供基础。

## 2. 主要功能

项目包含以下场景、资源或功能模块：

- RoboMaster 场地与三维模型资源
- 步兵机器人场景
- 子弹场景与发射相关逻辑
- 据点相关场景
- HUD 用户界面
- Godot 向 Python 发送图像的相关脚本
- Godot 接收 Python 命令的相关脚本

**说明：** 上述内容涵盖项目当前包含的模块和开发方向。各项功能的具体完成程度以当前代码和实际运行结果为准。

## 5. 安装与运行

### 5.1 获取项目

在终端中执行：

```bash
git clone https://github.com/Lengendhall/robo-master-model-lab.git
cd robo-master-model-lab
```

### 5.2 使用 Godot 运行

1. 安装 Godot 4。
2. 打开 Godot 项目管理器。
3. 导入项目目录中的 `project.godot` 文件。
4. 等待 Godot 完成资源导入。
5. 打开项目并运行主场景。

如果项目启动失败，可以检查 Godot 版本、资源导入状态和主场景配置。

### 5.3 Python 通信程序

项目包含与图像发送和命令接收相关的脚本。Python 端程序需要根据实际通信实现进行配置和启动。

Python 端的依赖安装、启动命令及通信参数将在进一步核对代码后补充。

## 7. 比赛规则与仿真简化

本项目是 RoboMaster 风格的仿真项目，并非完整的官方比赛模拟器。

开发重点主要集中在三维场景、机器人基础行为和视觉通信。受项目时间和开发范围限制，完整的比赛规则与机制尚未全部实现。

真实比赛中的裁判系统、机器人功率与热量限制、弹丸消耗、伤害判定、比赛计分及多机器人协同等机制，仍需根据当前实现情况逐项核对。

后续将进一步整理规则对照说明，区分：

- 已实现的仿真机制
- 经过简化的机制
- 尚未实现的比赛规则

在完成具体核对之前，不将未经验证的规则描述为已实现功能。

## 8. Godot 与 Python 通信

项目包含与图像发送和命令接收相关的脚本，目标是建立仿真环境与外部 Python 视觉程序之间的数据通路。

整体设计方向如下：

1. Godot 运行仿真场景。
2. Godot 将图像发送给 Python 程序。
3. Python 程序接收图像并进行处理。
4. Python 根据处理结果生成命令。
5. Godot 接收命令，并根据当前实现执行相应操作。

该流程用于探索仿真环境与外部视觉程序之间的通信方式，为后续视觉闭环开发提供基础。

实际支持的传输协议、消息格式、端口、图像分辨率、帧率和命令字段，需要根据通信脚本进一步确认。

目前的基础通信和识别功能不代表项目已经具备完整的自动瞄准或自主控制能力。

## 9. 已知问题与后续计划

受项目开发周期、任务分工和实现成本等因素影响，当前版本仍存在以下限制。

### 9.1 视觉识别功能尚未完善

在视觉通信与识别部分，项目保留了基础的视觉识别代码，并围绕 Godot 与 Python 之间的数据传输开展了相关工作。

由于进一步开发精细化视觉识别算法需要投入较多时间，且完整的视觉识别任务主要由视觉组负责，因此本项目没有继续独立开发完整、精细的识别流程。

目前保留的基础识别代码主要用于提供初步的识别功能和后续算法接入基础。更完整的识别算法仍需要结合视觉组的工作进行集成和完善。

### 9.2 完整比赛场景仿真尚未实现

开发过程中，项目已下载前几年 RoboMaster 比赛的完整场地地图资源，希望在此基础上进一步构建比赛仿真环境。

但由于项目时间有限，后续未能继续完成完整地图的进一步整合，也没有继续开发完整的比赛仿真机制。

因此，当前项目主要聚焦于已有场景、机器人基础行为和视觉通信，尚不能视为完整的 RoboMaster 比赛模拟器。

### 9.3 后续改进方向

后续可根据时间安排和团队协作情况，逐步推进以下工作：

- 接入并完善视觉组开发的识别算法。
- 提高图像传输与视觉处理流程的稳定性和流畅度。
- 进一步整合比赛场地模型，完善场景中的碰撞和交互。
- 根据实际需求补充比赛规则、机器人状态和比赛机制。
- 完善操作说明、通信协议和运行文档。
- 录制项目运行演示视频，展示当前已实现的功能。
